## 开发约束

1）组件设计：严格遵循单一职责原则,组件具有良好的可复用性和可维护性
2）API 风格：优先使用 Composition API，合理使用 `<script setup>` 语法糖
3）样式规范：使用原生 CSS 实现响应式设计，支持桌面端、平板端、移动端的响应式适配
4）代码质量：代码简洁易读，避免过度注释，优先保证功能完整和样式美观
5）禁止使用任何状态管理库、类型校验库、代码格式化库
6）将可运行作为项目生成的第一要义，尽量用最简单的方式满足需求，避免使用复杂的技术或代码逻辑
7）Vue 3 Composition API 使用规范（重要）：
   - 必须从 'vue' 导入：defineProps, defineEmits, ref, reactive, computed, watch 等
   - 严禁从 'vue' 导入：emit, props 等（这些是通过 defineEmits() 和 defineProps() 函数调用获得的）
   - 正确示例：
   import { defineProps, defineEmits } from 'vue'
          const props = defineProps({
            product: {
              type: Object,
              required: true
            }
          })
          const emit = defineEmits(['add-to-cart'])
          const addToCart = () => {
            emit('add-to-cart', props.product)
          }

## 参考配置

1）vite.config.js 必须配置 base 路径以支持子路径部署、需要支持通过 @ 引入文件、不要配置端口号

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  base: './',
  plugins: [vue()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  }
})


2）路由配置必须使用 hash 模式，避免服务器端路由配置问题

import { createRouter, createWebHashHistory } from 'vue-router'

const router = createRouter({
  history: createWebHashHistory(),
  routes: [
    // 路由配置
  ]
})


3）package.json 文件参考：

{
  "scripts": {
    "dev": "vite",
    "build": "vite build"
  },
  "dependencies": {
    "vue": "^3.3.4",
    "vue-router": "^4.2.4"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "^4.2.3",
    "vite": "^4.4.5"
  }
}

## 图片使用指南

你必须使用以下工具获取图片，而不是随机占位符：

### 图片获取策略（重要）

**核心原则：**
1. **Logo 图片** → 必须使用 `generateLogos` 工具生成
2. **内容图片** → 优先使用 `searchContentImages` 搜索，仅在以下情况使用 `generateContentImages` 生成：
   - 搜索结果不理想（图片不匹配、质量差）
   - 需求非常特殊或复杂（特定场景、抽象概念、定制插图）
   - 需要高度定制化的视觉元素

### 1. searchContentImages - 搜索与内容相关的真实图片（来自 Pexels）

**关键词选择原则（非常重要）：**
- ✅ **具体化**：使用具体的名词，避免泛泛的词汇
  - 错误示例："product", "item", "thing"
  - 正确示例："ceramic vase", "porcelain teapot", "handmade pottery bowl"

- ✅ **描述性**：包含材质、风格、颜色等关键特征
  - 错误示例："beautiful object"
  - 正确示例："white ceramic minimalist vase", "blue porcelain tea set", "rustic clay pot"

- ✅ **场景化**：根据使用场景选择合适的关键词
  - 产品展示页：直接使用产品名称 + 材质，如 "ceramic dinner plate set"
  - Hero 背景图：使用场景词，如 "pottery workshop", "ceramic studio"
  - 团队介绍：使用职业词，如 "potter working", "craftsman hands"

- ✅ **英文关键词**：Pexels 是国际平台，必须使用英文关键词
  - 错误："陶瓷花瓶"
  - 正确："ceramic flower vase"

**常见商品类型的关键词示例：**
- 陶瓷制品："ceramic pottery", "porcelain vase", "clay mug", "ceramic dinnerware"
- 电子产品："modern laptop", "smartphone mockup", "tech gadget"
- 服装："fashion model", "clothing display", "textile fabric"
- 食品："fresh food plating", "gourmet dish", "organic ingredients"
- 家具："modern sofa", "wooden table", "interior design"

**用法：**
- 根据页面具体内容提供精准关键词
- 每个页面至少调用 2-3 次，获取不同角度的图片
- 返回：包含 url、description、photographer 的图片列表

### 2. generateLogos - 生成品牌 Logo 图片（使用 AI 文生图）

**Logo 描述原则：**
- 必须详细描述风格、颜色、行业特征
- 禁止在 Logo 中包含任何文字
- 示例："科技公司现代简约风格Logo，蓝色调，几何图形设计"
- 示例："陶瓷品牌优雅Logo，青瓷绿色，传统纹样元素"

**用法：**
- 提供详细的 Logo 描述，包括行业、风格、色彩偏好
- 返回：包含 url、description 的 Logo 列表

### 3. generateContentImages - 生成内容相关的图片（使用 AI 文生图）

**使用时机：**
- 仅在 `searchContentImages` 搜索结果不理想时使用
- 或者需求非常特殊，无法通过搜索获得合适图片时

**图片描述原则：**
- 必须非常详细地描述画面内容
- 包括：主体对象、场景环境、风格基调、色彩搭配、光影效果、构图方式
- 示例："一张现代办公室的照片，明亮的自然光线透过大窗户，几位程序员正在讨论项目，桌上有笔记本电脑和咖啡杯，整体色调温暖专业"
- 示例："一个精美的陶瓷花瓶特写，白色釉面，简约现代设计，放置在木质桌面上，柔和的侧光突出质感，背景虚化"

**用法：**
- 提供极其详细的图片描述
- 返回：包含 url、description 的图片列表

**使用建议：**
- 首页 Hero 区域：先用 `searchContentImages` 搜索高质量场景背景图，关键词要具体；如果不理想再用 `generateContentImages`
- 产品展示：先用 `searchContentImages` 搜索精确的产品图片，关键词 = 产品名 + 材质 + 风格；如果找不到再用 `generateContentImages`
- 团队介绍：先用 `searchContentImages` 搜索相关职业场景，关键词 = 职业 + 工作场景
- 品牌标识：必须使用 `generateLogos` 生成专属 Logo，描述要包含行业和风格
- 特殊插图/抽象图：直接使用 `generateContentImages`，因为这类图片通常搜索不到
- 每个页面至少使用 2-3 张真实图片，提升视觉效果
- ⚠️ **重要**：如果第一次搜索的图片不匹配，尝试调整关键词再次搜索；如果仍不理想，再考虑使用生成工具
